# TCK-102 · API returns HTTP 500 for trades that don't exist
**Customer:** Northbridge Bank · **Reporter:** Tom Becker, Integration Team · **Version:** 2.4.0

> Our reconciliation job calls `GET /api/v1/trades/{id}` for every trade in our books.
> When a trade was deleted, RiskCube answers **500 Internal Server Error**. Our monitoring treats every 5xx as an
> outage of RiskCube and pages our on-call engineer at night (3 times last week).
> A missing trade is not a server error. Could you return a proper 404 with a readable body?

**Expected:** `404` with `Content-Type: application/problem+json` (RFC 7807). Bonus: include the `requestId`.

**Test:** `Tck102NotFoundReturns500Test`
